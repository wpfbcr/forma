# 个人 AI 工作台 · 产品定义 v0.1

状态：产品讨论稿；所有功能均为规划，不表示已经实现。日期：2026-10-29。

## 1. 定位与用户

一句话定位：一个本地优先、支持多模型的开源个人 AI 工作台，让用户创建自己的 Agent 与团队，也能接入本机已有的成熟 Agent，围绕任务协作并交付可使用的成果。

首版目标用户已确认：个人进阶用户，兼顾编程、研究、写作和日常工作，包括独立开发者、研究者和内容创作者。Agent 与 Agent Teams 均由用户创建、选择和管理，职责与团队组成不由平台固定。模板只作为用户选择使用的创建起点，创建后形成用户自己的可编辑配置。产品不预设所有工作都围绕代码仓库展开。

产品承诺：接入自己选择的模型；保留自己的工作资料；看懂团队正在做什么；随时介入；拿到有来源、可编辑、可导出的成果。

产品边界已确认：Magpie 仅作为模型接入与路由环节的参考。平台完整覆盖工作空间、任务、Agent、团队协作、记忆、工具和成果管理。是否直接集成 Magpie、复用其代码或独立实现路由，留到技术选型阶段决定；参考产品不等于确定技术依赖。

完整产品可分为五个层次：工作台承载用户目标与成果；团队协调层负责分工、依赖和验收；Agent 执行层负责模型调用、工具执行与过程状态；模型接入与路由层负责选择和连接模型；工作空间、记忆、权限与执行记录为各层提供共同基础。Leader 决定谁做什么，模型路由决定某次模型请求由哪个已配置的模型服务处理，两者职责独立。

桌面端支持 Windows 与 macOS，提供安装包与源码运行/构建两种路径。首版不强制注册平台账号。云模型仍需要相应服务商账号或密钥；使用云模型时，会按任务需要向该服务商发送内容，本地优先不等于所有推理离线。

## 2. 核心使用闭环

安装 → 自建 Agent 或接入本机已有 Agent → 单独使用或组建个人团队 → 指定目标与资料 → 查看计划 → 执行与介入 → 验收成果 → 保存经验或复用团队。

首次使用提供两个并列入口：“创建 Agent”与“接入已有 Agent”。自建路径要求模型连接成功；已有 Agent 路径检查本机安装与可调用状态，优先使用该 Agent 自己支持的认证和配置，不要求用户先在平台重复添加模型。随后选定工作目录，运行一个示例任务。工具、记忆策略、备用模型、画布均可稍后配置。首次成功目标建议定为十分钟内完成一项真实小任务，属于待验证的体验目标。

首版场景覆盖：编程任务交付代码修改与验证结果；研究任务交付带来源的分析；写作任务交付可编辑稿件与修订；日常工作任务交付资料整理、会议纪要、计划或文件处理结果。四类场景复用同一套任务、团队和成果机制，通过模板与工具差异提供不同体验。自动定时执行与对外发送并非这些场景默认包含的能力。

普通聊天、单 Agent 执行和团队执行共用任务入口。简单问答直接由单助手回答；需要分工时由用户选择团队，或接受系统建议切换，切换前展示新增成员和资源预算。

## 3. 概念与归属

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 工作空间 | 一个项目或长期主题的资料、目录、约定和任务集合 | 可运行多个任务，复用多个团队 |
| 服务商连接 | 访问模型的入口，含地址、认证、协议与连接状态 | 一个服务商可有多个模型 |
| 模型配置 | 可调用的模型及其能力、参数和可选备用项 | 可被多个 Agent 使用 |
| 个人 Agent | 用户创建的可复用执行角色，来源为自建配置或已接入的成熟 Agent | 可独立使用，也可加入多个团队 |
| Agent 模板 | 用户可选择复制的创建起点，包括角色与执行配置 | 复制后成为个人 Agent，不固定用户的职责与工具选择 |
| 已接入 Agent | 用户选择接入的本机成熟 Agent，如 Codex、Claude Code | 记录执行入口与经验证的能力，按其实际支持范围配置 |
| 团队成员 | 个人 Agent 在某个团队中的角色、职责与配置覆盖 | 同一 Agent 可在不同团队承担不同职责，运行上下文分别隔离 |
| 团队 | 用户选择 Leader、添加多个成员并定义协作与交付规则的个人团队 | 可混合自建与成熟 Agent，跨任务复用，修改产生配置版本 |
| 任务 | 用户要完成的目标、输入、验收条件与成果 | 一次任务可有多次执行记录 |
| 执行记录 | 一次执行的计划、成员状态、工具操作、费用和检查点 | 固定使用启动时的团队配置版本 |
| 成果 | 可预览、编辑、导出的文件或结构化结果 | 关联任务、版本和来源 |

修改 Agent 模板不会静默改变正在运行的团队。团队配置与当前运行分开保存；应用新配置或替换模型应在明确的恢复点生效并记录。

## 4. 主界面与视觉方向

主导航保持少量入口：工作台、团队、资源、设置。

- 工作台：按工作空间组织任务；默认显示继续上次工作与新建任务入口，运行中和待处理任务优先。
- 团队：我的团队、我的 Agent、可选模板；支持从零创建、快捷创建和画布编辑。Agent 库提供“创建 Agent”“接入已有 Agent”两个入口，清楚标注来源。
- 资源：模型、工具、资料与记忆的统一管理；在任务内也可直接添加所需资源。
- 设置：外观、存储、备份、更新、诊断与隐私。

执行页采用三部分：左侧任务导航，中间与 Leader 的交互及成果，右侧按需展开的团队进度/文件/操作详情。右侧默认可收起。中间顶部固定显示任务名、状态、暂停/继续和停止入口。

用户首先看到当前计划、正在执行的步骤、遇到的阻碍和成果。成员之间的消息按需展开；详细记录呈现任务摘要、工具调用和结果，不要求或承诺展示模型的内部思维链。

视觉原则：中性底色、单一强调色、清晰文字层级、充分留白、轻分割、克制动效、浅色/深色主题。颜色用于选中与状态，状态同时有文字。遵循两种系统各自的窗口、快捷键、文件选择习惯。键盘可操作，文字可缩放。

## 5. 模型中心

用户已确认参考来源为 yetone/magpie，且其参考范围仅限于模型接入与路由这一环。其官方说明展示了“添加服务商 → 选择模型 → 分配给 Agent”、预设服务商、统一模型列表和路由组等设计。这里借鉴交互分层，不预设需要复制全部网关与订阅适配能力，也不以模型路由作为整个平台的定位。

来源：https://github.com/yetone/magpie#providers

建议流程：选择服务商预设或自定义连接 → 输入必要认证与地址 → 获取模型列表或手动填写模型标识 → 运行连接与能力测试 → 保存 → 分配给助手/团队成员。

区分连接可达、认证成功、模型可用、工具调用可用四类状态；“可聊天”不能被当成“适合执行 Agent 任务”。展示已验证能力与未知能力，允许显式配置覆盖。模型能力至少涉及文本、图像输入、工具调用、结构化输出和上下文限制。

首版规划：云 API、自定义兼容服务、本地模型服务；按 Agent 单独选模型；参数预设；模型搜索和收藏；连接测试。每种协议应单独验证，不承诺任何兼容地址都能完整工作。

后续规划：备用模型、预算优先/质量优先策略、路由组和更丰富的接入适配。备用模型需要满足当前任务能力与数据边界；切换写入执行记录，不跨服务商静默扩大数据发送范围。

首版允许填写价格并按返回用量估算费用；价格未知则显示用量和“费用未知”，不得显示为零。估算费用与服务商账单分开标识。

## 6. Agent 的产品形态

Agent 由用户打造，提供两种来源并允许统一参与团队：

1. 自建 Agent：用户命名并定义职责，选择模型、工具、记忆、工作方式与目录，由平台执行引擎运行。基础配置先展示名称、职责、模型；高级配置按需展开。
2. 接入成熟 Agent：用户选择本机已安装的 Codex、Claude Code 等工具，或手动指定其可执行入口；平台检查安装、版本、认证状态与可调用性，用户指定工作目录和团队职责后即可在支持范围内使用。检测到安装不等于已验证可执行，不在检测时擅自更改其全局配置或迁移凭据。

接入现有 Agent 不是仅借用同名模型，而是调用该 Agent 自身的执行能力。界面展示“来源/执行方式”，并为外部 Agent 提供“沿用自身配置”选项。名称、职责与交付目标可由平台管理；模型、工具、记忆、权限等字段只在对应适配已验证时开放修改，否则显示由原 Agent 管理或尚不支持。

| 维度 | 用户可设置内容 |
| --- | --- |
| 职责 | 擅长事项、职责边界、应向谁交接、完成标准 |
| 模型 | 自建 Agent 选择主模型、参数预设；成熟 Agent 沿用自身配置或通过已验证适配修改；后续增加备用模型与预算策略 |
| 工作方式 | 直接执行、先计划后执行、研究后回答、审阅与反馈 |
| 工作目录 | 当前任务目录或成员独立目录；分别指定可读取和可写入位置 |
| 记忆 | 可读取哪些长期记忆、可提出哪些记忆更新、是否跨任务复用 |
| 工具 | 启用的工具、参数、访问范围、需要用户确认的操作 |
| 交付要求 | 文本、文件、结构化数据、测试/检查结果等 |

工作方式描述解决问题的步骤；权限决定能做什么，两者不能混为“自主程度”。用户可以让 Agent 自动研究但限制写文件，也可以只允许某个目录内自动写入。

平台执行引擎与第三方 Agent 执行器都是产品的核心接入路径。首版规划同时覆盖自建 Agent 与本机 Codex、Claude Code 的接入，具体支持版本与调用方式需在技术验证阶段确定，不再将外部 Agent 整体推迟到后续版本。

适配需逐项验证任务下发、工作目录、输出读取、完成/失败识别、取消、恢复、工具与权限控制、模型切换、用量获取。统一呈现的是任务、角色、状态与成果，不假定所有执行器拥有相同能力。缺少实时进度或费用时明确显示未知；不支持暂停时说明只能停止新任务派发或使用其已验证的取消方式。权限规则必须可实际执行，不能只通过角色提示词宣称已隔离。

平台共享记忆与原 Agent 自己管理的记忆分别标识。只有通过明确的适配才能注入任务资料或同步指定内容，不自动合并各 Agent 的全部历史记忆。同一成熟 Agent 的多个并发成员需要独立会话和目录；若不能可靠隔离，则限制并发。

## 7. 团队创建与运行

### 两种必备创建方式

快捷创建：用户命名团队，从“我的 Agent”选择成员并指定 Leader，设置目标与工作空间即可创建；也可以先选择研究、写作、开发、日常事务等模板再调整成员。创建过程中可直接新增自建 Agent 或接入已安装 Agent。可以添加“一句话生成草稿”，但生成后仍使用同一套可编辑配置，由用户决定采用。

画布创建：从个人 Agent 库添加成员，指定 Leader，拖动排列，设置汇报关系和交接规则，点击节点打开配置侧栏。节点同时标注用户角色名与执行来源，避免把角色和底层工具混淆。提供键盘/列表等价编辑入口。快捷模式与画布始终编辑同一个团队定义，支持双向切换而不丢配置。

画布中的组织关系表达“谁向谁汇报”；任务依赖表达“谁完成后谁开始”。两种连线分视图展示并标注含义。首版采用一个 Leader 加多个成员的结构，不做嵌套团队；任务执行时依据计划呈现实际依赖。

### Leader 的职责

Leader 是用户为团队指定的协调角色，不是平台固定且不可替换的人物。用户可创建专门的 Leader Agent，也可以选择具备已验证协调接口的成熟 Agent 承担该角色。若某个外部 Agent 暂不具备协调适配，仍可作为执行成员，界面明确说明；不能仅凭名称或已安装状态就标记其可担任 Leader。

理解目标和验收条件；拆分任务；分配合适成员；控制并发、轮数和预算；汇总结果；识别冲突和缺口；发起有限返工；提交最终成果。Leader 无权绕过成员权限和用户设置的资源上限。

协作模式首版覆盖 Leader 派发后的并行执行与按依赖顺序交接；审阅成员可提供反馈，Leader 决定是否在限额内返工。后续再增加复杂辩论和多层团队。

### 一次具体运行

用户提出“调研某类工具并输出选型报告” → Leader 拆成资料收集、事实核查与报告整合 → 调研员提交带来源的材料 → 审阅员核对关键结论 → 写作者整理报告 → Leader 检查验收条件并交付。

用户始终可以补充要求、查看成员、暂停、停止或要求重做某一部分。补充要求由 Leader 记录为任务变更，再分派给受影响成员。

### 运行边界

- 运行状态：待开始、规划中、执行中、等待用户、暂停中/已暂停、已完成、失败、已停止。
- 成员状态：待命、执行、等待依赖、受阻、完成、失败。
- 暂停阻止新步骤派发；已发出的外部调用可能需结束或超时后才停下，界面应显示正在暂停。
- 限制成员数、并发数、总调用/轮数、执行时长与费用预算，达到限额后停止新调用并提示用户；已在途请求可能仍计费。
- 成员失败可在有限次数内重试或由 Leader 重新分派，界面保留失败原因，不静默无限循环。
- 多成员使用独立草稿/目录，成果由明确的整合步骤合并；代码场景可后续使用隔离工作树。不得让并行成员无协调地覆盖同一文件。
- 检查点用于恢复已完成阶段。恢复不盲目重放发消息、购买、发布等外部写操作；无法确认状态时向用户报告。

## 8. 记忆、资料与工具

资料库保存用户提供的文件和检索来源；记忆保存从长期工作中提炼且允许复用的偏好、规则与经验；任务上下文保存当前任务的进展。三者可以关联，但分别管理。

记忆作用域：个人偏好、工作空间、团队/角色、当前任务。工作空间之间默认不共享业务资料；角色记忆也必须受工作空间边界约束。用户可查看、编辑、删除、关闭记忆，并查看每条记忆的来源与更新时间。跨任务长期写入先生成可审阅建议；在明确开启自动记忆后才自动保存。记忆是上下文资料，不能覆盖用户指令与权限规则。

工具中心统一呈现内置工具与扩展工具。首版优先支持文件读写、搜索/网页读取、受限命令执行和基础 MCP 接入。Skills 表示复用的工作方法，工具表示可执行的动作，二者在界面上区分。

工具需显示可用状态、配置缺项、作用范围和最近错误。权限按当前任务/工作空间/工具配置；读取、写入、命令执行和对外发布分开处理。需要确认时给出具体动作与目标，不仅显示“是否授权”。

## 9. 首版范围与后续版本

| 阶段 | 用户能完成什么 | 主要范围 |
| --- | --- | --- |
| 原型验证 | 验证用户能否创建/接入 Agent、快速建队、看懂分工和验收成果 | 自建与已有 Agent 双入口、模型添加、快捷建队、简化画布、任务执行页的交互验证；同步验证外部 Agent 可调用能力 |
| 首个可用版本 | 自建与已安装的成熟 Agent 可独立工作并参与同一团队 | Windows/macOS、安装包与源码路径、模型连接、个人 Agent 创建、本机 Codex/Claude Code 适配、用户创建的单 Leader 团队、快捷/画布双入口、基础工具、文件成果、执行记录、能力感知的暂停/停止、资源限制、基础记忆 |
| 体验增强版 | 更可靠地运行长任务并复用个人积累 | 自动恢复、能力匹配的备用模型、检索增强资料库、版本比较、更多模板和模型适配 |
| 扩展生态版 | 接入更多执行器、分享模板并运行自动任务 | 更多第三方 Agent 适配、模板目录、定时任务、可选同步与远程执行 |

首版交付格式优先文本、Markdown、代码和通用文件预览。Office、PDF 的高质量生成与编辑可通过后续工具扩展，不在第一版承诺完整专业编辑器。

首版不包含多人组织协作、复杂企业权限、无限层级团队、完整工作流编程语言、移动端或托管模型计费。这些不影响核心个人工作闭环。

## 10. 分发与开源体验

安装包版本让用户安装后直接进入引导，无需先安装开发环境；模型本体不随包附带，连接本地推理服务时按需引导。源码路径提供明确版本要求、一键启动入口和打包说明。两条路径使用同一数据格式与功能定义。

Windows 与 macOS 明确列出经过验证的系统版本和架构，按发布矩阵产出安装包；安装、升级、卸载的数据保留行为应可预测。更新前备份配置，支持可诊断的迁移。签名与 macOS 公证列为正式分发工作，具体平台流程在开发阶段验证。

密钥使用系统凭据存储或适当的本地安全存储；导出团队模板不携带密钥、绝对路径、私人记忆或执行日志。导入模板后映射本机模型、工作目录与工具，展示缺少项。允许导出与备份用户自己的任务、成果和配置。

开源仓库应提供许可证、快速开始、架构说明、贡献指南、问题模板、示例团队与发布说明。许可证选择在立项时单独确认，不由本稿替用户决定。

## 11. 验证标准与待确认项

产品验证重点：新用户首次任务成功率、建队所需时间、任务成果通过验收的比例、人工介入频率、失败后恢复成功率、同类任务耗时与成本。需要比较单 Agent 与团队结果，确认多 Agent 带来实际收益。

首版验收示例：两种操作系统均能安装启动；用户可从零创建 Agent 和团队；可以接入至少两种已验证的模型服务类型；同一团队中不同成员使用不同模型；已安装且认证可用的 Codex/Claude Code 可经验证接入并执行任务；自建与成熟 Agent 可在一个团队中交接成果；已有 Agent 路径不强制重新配置平台模型；快捷与画布配置往返不丢失；执行状态和最终成果一致；失败与不支持的能力能明确报告；权限与资源限制按实际支持范围有效执行；重启后能找回任务记录与文件；模板导出不含密钥。

已确认：面向个人进阶用户，兼顾编程、研究、写作和日常工作；Magpie 指 yetone/magpie，仅作为模型接入与路由环节的参考；Agent 与 Agent Teams 均由用户创建和管理，并支持使用本机已安装的 Codex、Claude Code 等成熟 Agent。

当前待确认：用于最先验证完整闭环的具体示例任务。技术验证待办：外部 Agent 在 Windows/macOS 上的具体可调用入口、支持版本、认证复用方式、权限与进度可观测性，以及可担任 Leader 的适配条件。此前“仅内置执行引擎优先、外部 Agent 后置”的建议已被用户澄清替代。

## 12. 任务工作空间与持续对话（已确认方向）

每次从工作台开始新任务时，先创建一个独立工作空间，允许用户命名。空间归档本次任务的全部输入资料、过程文件、上下文、对话和成果。现阶段 HTML 演示使用浏览器内的虚拟目录；正式桌面版再映射到用户选定的真实目录。

布局：左侧为应用导航和任务入口，中间为用户与 Team Leader 的持续对话，右侧为当前工作空间。右侧包含“资料 / 上下文 / 执行”三个页签。窄窗口以“对话 / 工作空间”切换呈现，保留可见的发送入口。

用户只与 Team Leader 对话，成员不直接进入用户聊天。Leader 理解需求、拆解任务、派发成员、收集结果、审阅并统一交付。用户可在侧栏检查派发内容、成员进度和中间资料。

一项任务可连续执行多轮。完成后继续提出要求时，沿用同一空间的历史对话、工作摘要、资料与已有成果，生成新版本。执行期间新增要求先进入待处理列表，当前轮完成后再开始下一轮；用户仍可显式暂停或停止。进度和分工等状态追问不应触发完整的新一轮执行。

上下文管理区分：完整用户—Leader 对话、摘要、每轮上下文快照、成员任务简报。Leader 可以使用该任务的完整历史；成员接收与本职任务相关的要求与资料，不自动获取其他任务的历史。每轮启动时记录其使用的资料、记忆及前序成果版本，后续变更在下一轮生效。

工作空间至少包含：任务目标、参考资料、每轮计划、成员中间产物、Leader 上下文、完整对话、执行记录、最终成果和历史版本。用户可预览和下载文件，或完整导出空间。上下文展示工作事实、约定与可观察的执行过程，不承诺展示模型内部思维。
